# 0.2.5 验收记录

日期：2026-11-25。Windows x64、Rust 1.99.0、MSVC、Slint 1.19.1、rquickjs 0.14.0、libmpv bcde6b93cc。

## 0.2.5：横屏与竖屏切换保持窗口长宽比

- 修复 0.2.4 将窗口宽高按屏幕宽高分别缩放的问题。先比较屏幕长边与长边、短边与短边，取两者比值中较小的作为同一个缩放倍数，窗口宽高一起缩放。
- 工作区上限和最小窗口尺寸也转换成同一倍数的上下限，避免只限制宽或高再次改变窗口比例。如果工作区无法容纳满足最小尺寸的等比窗口，保留最小尺寸和窗口比例。物理像素分别取整，允许最多 1 像素的舍入误差。
- 先添加回归复现：原算法将 4K 横屏上的 1500×1050 窗口变成竖屏上的 720×1244；修复后为 1000×700。相同分辨率仅旋转方向时，能放下的 1000×700 窗口尺寸不变；较大窗口放入竖屏时等比收缩。覆盖反向切换、100 次往返以及最小尺寸和工作区约束。
- 隐藏原生窗口回归新增横竖屏切换，并独立验证 Windows 最终窗口长宽比，仅允许像素舍入误差。本机 3840×2160 / 150% 与左侧竖屏 1440×2560 / 100% 往返通过；继续检查 DPI、拖后边框缩放、缓存与渲染尺寸及标题栏主题。测试注入窗口自己的拖动坐标，未操作桌面鼠标或正在运行的播放器，不等同于人工标题栏拖动验收。
- 检查通过：`cargo fmt --all --check`、`cargo clippy -p music-app --all-targets --all-features -- -D warnings`、`cargo test --workspace`（23 项）。

下文为历史记录。0.2.4 的宽高独立缩放规则已由上述等比缩放替代。

## 0.2.4：按占屏比例跨显示器拖动

- 按用户确认的规则替换 0.2.2/0.2.3 的固定物理尺寸与固定启动缩放。每次进入原生拖动循环，记录窗口外框、起始显示器分辨率、DPI 和鼠标抓取位置；仅移动窗口时执行比例换算，边框缩放仍使用系统交互。
- `目标外框宽 = 起始外框宽 × 目标屏幕宽 / 起始屏幕宽`，高度独立计算。始终从起始快照计算并取整，不在中途尺寸上累乘；目标由鼠标位置确定，支持显示器在主屏左侧、上方及竖屏。DPI 用于目标界面、输入坐标、标题栏抓取偏移与最小尺寸，不再次乘到窗口像素尺寸上。
- 通过 Win32 窗口 subclass 接入 `WM_ENTERSIZEMOVE`、`WM_MOVING`、`WM_WINDOWPOSCHANGING`、`WM_EXITSIZEMOVE`；Windows/winit 自带的 DPI 缩放与位置修正不能覆盖当前拖动矩形。保留过期 `Resized` 过滤，并处理鼠标松开后才送达的 DPI 事件。窗口销毁时移除 subclass 并释放状态。
- 目标尺寸遵守 720×480 逻辑像素最小内容区；在能满足最小尺寸时以目标工作区为上限。遇到边界约束时不能严格保持原占屏比例。拖动结束后边框可继续自由调整；下次拖动重新取快照。原生标题栏主题不变。
- 几何回归覆盖 1080p→4K 在 100%/125%/150%/200% DPI 下宽高乘 2、同分辨率不同 DPI、100 次往返无累积误差、负坐标、横竖屏、工作区及最小尺寸、新拖动采用调整后的窗口。
- 隐藏 Slint 窗口回归执行真实的进入/移动/退出消息和 `SetWindowPos`，穿插 `WM_DPICHANGED`，包含 DPI 消息在退出拖动后才被框架处理的情况。每步核对原生外框、客户区、Slint 缓存、实际渲染尺寸、内容 DPI、最小限制及深浅标题栏颜色。
- 本机真实显示器：3840×2160 / 150%，以及左侧竖屏 1440×2560 / 100%（坐标 -1440,-219）。隐藏测试窗口在这两块屏幕间往返，使用系统查询的分辨率、工作区和 DPI，系统自动产生的 DPI 通知未覆盖目标尺寸。测试为自己的窗口注入拖动指针坐标，没有移动桌面鼠标或操作现有播放器；不等同于人工标题栏拖动验收。
- 检查通过：`cargo fmt --all --check`、`cargo clippy -p music-app --all-targets --all-features -- -D warnings`、`cargo test --workspace`（21 项）。本次未重跑联网播放或真实账号读写。

下文为历史记录，其中固定启动缩放的行为已由 0.2.4 的占屏比例规则替代。

## 0.2.3：窗口缩小与标题栏主题

- 复现两个最小尺寸问题：旧布局下限过大；创建窗口时传给 winit 的逻辑尺寸约束仍会按新屏幕 DPI 放大。上一版只测了放大窗口，遗漏了拖动缩小的约束。
- 将最小内容区降为 720×480 逻辑像素，并以播放器自身的固定缩放比例转换为原生物理尺寸约束。回归中切到 200% DPI 后，修复前最小外框仍涨到 1462×1016；修复后在相同内容缩放下保持原下限。
- 主 FocusScope 明确贴合窗口边界，内容布局不再反向参与窗口的尺寸推导；窄窗口调整侧栏、播放栏、设置页、歌词和歌曲列，卡片使用两列。
- 保留原生标题栏和边框交互，通过 winit Windows 扩展同步主题背景、文字及边框颜色，增加播放器图标。更早 Windows 不支持精确标题栏配色时保留原生深浅主题。
- 将窗口回归扩展为 `resize_dpi_and_native_theme_regression`：查询 `WM_GETMINMAXINFO` 和可缩放标志，覆盖 720×480、960×620、1240×820 及连续尺寸事件；每次 DPI 切换后再次检查最小限制、原生/Slint/渲染尺寸与缩放比例。
- 同一回归用 `DwmGetWindowAttribute` 读取实际标题栏背景、文字和边框颜色，检查深浅主题切换；最小窗口检查空状态、歌曲、卡片、设置和歌词渲染。截图来自隔离测试数据，未操作现有播放器或账号。
- 设置 `MUSIC_API_WINDOW_PREVIEW_DIR` 为已有目录可保存测试渲染图。它们只包含内容区；标题栏由上述原生属性读回校验。本次未执行鼠标拖动的端到端验收。
- 检查通过：`cargo fmt --all --check`、`cargo clippy -p music-app --all-targets --all-features -- -D warnings`、`cargo test --workspace`（16 项）。本次未重新执行联网播放或账号读写验证。

## 0.2.2：跨显示器拖动与 DPI

- 问题场景：拖到另一块缩放比例不同的显示器时，窗口与文字一起变大。Windows 的 DPI 变化通知会触发 winit 调整窗口尺寸，Slint 同时调整界面比例。
- Windows 主窗口在本次运行期间保留创建时的 Slint 比例；跨屏 DPI 事件通过 `InnerSizeWriter` 保持当前内容区的物理像素尺寸。系统边框与标题栏仍由 Windows 管理。
- 丢弃与当前原生窗口尺寸不符的过期 `Resized` 事件。回归发现 DPI 修正后的尺寸事件可能先到，旧尺寸随后才到；直接应用旧事件会让下一次跨屏使用错误尺寸。
- 真实的手动尺寸变化继续传给 Slint；最大化、最小化和全屏时不强制恢复普通窗口尺寸。没有修改标题栏的双击或拖动消息。
- 新增隐藏 Windows 窗口回归 `monitor_dpi_changes_preserve_size_and_zoom`，发送 `WM_DPICHANGED` 覆盖 100%、125%、150%、200% 往返与中途手动调整大小；逐步校验原生窗口、Slint 缓存、渲染快照尺寸和界面比例。
- 修复前该回归失败（1500×1230 变成 1000×820）；修复后通过。该测试只创建自己的隐藏窗口，不操作现有播放器、账号或桌面鼠标。
- 检查通过：`cargo fmt --all --check`、`cargo clippy -p music-app --all-targets --all-features -- -D warnings`、`cargo test --workspace`（16 项）。本次未重新执行联网播放或账号读写验证。
- 本轮桌面操作由用户按 Esc 停止，之后未继续操作桌面。以上是原生事件与实际渲染回归，不等同于人工跨两块显示器拖动验收。

## 0.2.0 基础功能


保留 Slint + Rust + libmpv，将在线源运行时从 Wasmi 换为 QuickJS。主程序默认只有本地源，网易云以独立 `netease.ypm.zip` 交付。没有引入 Flutter 或 Node 服务。

界面重做侧栏、推荐头图、封面卡片、歌曲列表、底部播放栏、歌词页、队列抽屉、插件设置及明暗主题。为日常访问调整了网易云导航顺序；首页直接显示每日推荐和云盘入口。源码没有复制参考工程的 Flutter UI。

## 交付

```powershell
./scripts/build-windows.ps1 -OutputName MusicPlayer-windows-x64-0.2.5
```

主程序包 `dist/MusicPlayer-windows-x64-0.2.5.zip` 与插件 `dist/netease.ypm.zip` 分开。升级时直接导入 JS 包，不先卸载旧源，以保留原加密账号数据。旧 `.wasm` 文件不再被新版识别。

## 界面检查复现

只在测试构建启用快照辅助功能，正常 release 不包含自动截图/退出逻辑：

```powershell
cargo build -p music-app --features ui-smoke
$env:MUSIC_API_DATA_DIR = "$PWD/.test-data"
$env:MUSIC_API_MPV = "$PWD/dist/native/mpv-2.dll"
$env:MUSIC_API_CAPTURE = "$PWD/.test-data/render.png"
# 测试数据目录需先安装/启用 JS 插件
$env:MUSIC_API_CAPTURE_SOURCE = 'netease'
$env:MUSIC_API_CAPTURE_QUERY = '晴天'
$env:MUSIC_API_CAPTURE_PLAY = '1'
./target/debug/music-app.exe
```

15 秒后保存 Slint 自身渲染并退出。`MUSIC_API_CAPTURE_SCREEN` 可选 settings/lyrics/queue/login；`MUSIC_API_CAPTURE_THEME=light` 检查浅色主题，`MUSIC_API_CAPTURE_NAV` 按导航标题打开页面。开启 PLAY 会真实低音量播放。此方法检查应用回调、后台任务、音频与渲染，不等同于系统鼠标/键盘端到端验收。
